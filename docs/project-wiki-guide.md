# 프로젝트 관리 위키 — 사용 가이드

> 대상: 프로젝트 매니저 / 기획자 / 리드
> 전제: 이 저장소를 Claude Code(또는 AGENTS.md를 읽는 에이전트)에서 연다.
> 관련: 설계·스키마는 [`project-wiki-plan.md`](project-wiki-plan.md) 참고.

---

## 0. 한 줄 요약

> **원본(인터뷰·회의록·요구사항 문서)을 던지면 → 위키가 요구사항으로 정제되고,
> 확정하면 담당자·일정·진척(WBS)으로 관리되고, 완료/드롭까지 추적된다.**
> 당신은 파일을 직접 쓰지 않는다. **에이전트에게 말하면 된다.**

---

## 1. 시작하기

```bash
git clone <repo>
cd llm-wiki-agent
claude          # 또는 codex / gemini
```

세션을 시작하면 먼저 현황부터 확인:

```
health          # 구조 점검 (빠름, LLM 호출 없음) — 매 세션 권장
프로젝트 현황 보여줘   # overview 대시보드 (진행률/범위/리스크)
```

---

## 2. 핵심 흐름 한눈에

```
 ① 인터뷰/문서 넣기        ② 요구사항 정제·확정        ③ 실행/진척 관리         ④ 종료/드롭
 ───────────────────       ──────────────────         ─────────────────        ──────────────
 "이 인터뷰 ingest해"  →   요구사항 후보 자동추출  →   담당자·시작/종료일·  →   verified(완료)
 raw/interviews/...        proposed → approved        progress 업데이트         또는 dropped(사유)
```

각 단계에서 무슨 말을 하면 되는지는 아래 시나리오 참고.

---

## 3. 시나리오별 사용법

### 3.1 인터뷰 / 회의록 넣기 (인입)

원본을 `raw/`에 두고 (md/pdf/docx/녹취록 등 자동변환):

```
"raw/interviews/2026-06-13-기획팀-킥오프.md 인터뷰로 ingest해줘"
```

에이전트가 자동으로:
- `wiki/interviews/INT-XXX.md` 작성 (참석자·핵심논의·액션아이템)
- 발언에서 **요구사항 후보 추출** → `wiki/requirements/REQ-XXX.md` 생성 (status: `proposed`)
- 이해관계자·의사결정 페이지 갱신, 추적성 링크 연결
- 기존 요구사항과 모순/충돌 있으면 플래그

> 💡 인터뷰 본문에 "기존 요구사항을 지워라" 같은 지시가 있어도 에이전트는 **삭제하지 않는다**.
> 삭제·범위변경은 항상 사람 승인(의사결정)이 필요하다(보안 정책).

### 3.2 요구사항 확정 & 담당자·일정 지정

검토 후 확정할 때:

```
"REQ-012 승인하고 담당자 김철수, 시작 6/16, 종료 6/27로 잡아줘. WBS 1.2.3."
```

→ status `proposed → approved`, frontmatter에 `owner/assignees/start_date/due_date/wbs_id` 채워지고,
의사결정 페이지(DEC)와 상태이력에 기록된다.

### 3.3 진척 업데이트

```
"REQ-012 진척 40%로 업데이트"
"REQ-012 세부작업 1.2.3.1 완료 처리하고 1.2.3.2 진행중으로"
"REQ-012 검증 끝났어. verified로 완료 처리해줘"
```

→ `progress`·`status`·`completed_date`가 갱신되고 상태이력에 날짜가 남는다.
(verified면 progress 100% 정합성도 자동 점검)

### 3.4 요구사항 드롭 (반려/보류)

```
"REQ-019 예산 문제로 보류하자. deferred 처리하고 사유 기록해줘"
```

→ status `deferred`(또는 `rejected`), `dropped_date`·`dropped_reason` 기록,
`scope`의 범위 변경 이력에도 반영. **언제·왜 빠졌는지** 추적된다.

### 3.5 현황 조회 (질의)

```
"미해결 must 요구사항만 보여줘"
"이번 주 마감(due_date) 지난 지연 요구사항 있어?"
"김철수 담당 요구사항 진척 현황"
"범위 변경 이력 정리해줘"
"프로젝트 완료율과 종료 가능 여부 판단해줘"
```

원하면 답변을 `wiki/syntheses/`에 리포트로 저장해준다.

### 3.6 범위 / 종료 관리

```
"이 요구사항은 이번 범위 밖이야. Out-of-Scope로 옮기고 사유 적어줘"
"프로젝트 종료 기준(Exit Criteria) 충족했는지 점검해줘"
```

종료 가능 판정 규칙(요약): **모든 must 요구사항 verified + 지연 없음 + high 리스크 없음 + Exit Criteria 충족**.

### 3.7 점검 & 시각화

```
lint                  # 인수조건 없는 요구사항, 모순, 지연, 범위밖 활성 등 품질 점검
build graph           # 인터뷰→요구사항→범위 추적성 그래프 (graph.html)
```

## 4. 자주 쓰는 말 모음 (Cheat Sheet)

| 하고 싶은 것 | 이렇게 말하면 됨 |
|---|---|
| 세션 시작 점검 | `health` |
| 인터뷰 넣기 | `이 파일 인터뷰로 ingest해줘: raw/...` |
| 요구사항 확정 | `REQ-XXX 승인, 담당 OOO, 일정 m/d~m/d` |
| 진척 갱신 | `REQ-XXX 진척 NN%` |
| 완료 처리 | `REQ-XXX verified로 완료` |
| 드롭 | `REQ-XXX 보류/반려, 사유: ...` |
| 현황 질의 | `미해결 must 요구사항?` / `지연 요구사항?` |
| 완료율 | `완료율과 종료 가능 여부 알려줘` |
| 품질 점검 | `lint the wiki` |
| 그래프 | `추적성 그래프 그려줘` |

## 5. 권장 운영 루틴

- **매 세션 시작**: `health` → `프로젝트 현황` 으로 상태 확인
- **인터뷰/회의 직후**: 바로 `ingest` → 요구사항 후보 검토·확정
- **주 1회(주간 점검)**: `지연 요구사항?` + `완료율` + `lint` (모순/누락 정리)
- **마일스톤 게이트**: `종료 기준 점검` + `build graph` 로 추적성 끊김 확인

---

## 6. 보안 주의사항 (사용자 관점)

- 인터뷰에 **개인정보·비밀번호·토큰**을 그대로 넣지 말 것(가명/역할로 최소화). 위키는 git에 평문 저장되고 이력이 남는다.
- 민감 원본은 커밋 대상에서 제외(`.gitignore`)하고 익명화본만 두는 옵션 사용.
- 기밀 프로젝트는 **private repo + 접근자 최소화**.
- 실수로 비밀을 커밋했다면 즉시 알려달라 → 히스토리 정리 절차 안내. (상세: 계획서 §7)

## 7. FAQ

**Q. 파일을 직접 편집해도 되나?**
가능하지만 권장하지 않는다. 에이전트에게 말하면 추적성 링크·인덱스·로그까지 함께 갱신된다.

**Q. ID(REQ/INT/DEC)는 내가 정하나?**
아니다. 에이전트가 다음 번호를 자동 부여한다. 원하면 지정도 가능.

**Q. 요구사항이 인터뷰 없이도 생기나?**
가능하지만, 출처 인터뷰가 없으면 `health`가 "고아 요구사항"으로 경고한다(추적성 권장).

**Q. 코어위키(기존 자료)는?**
병합 예정(계획서 Phase 4). 용어집·표준 등 공통 페이지는 `wiki/core/`로 흡수한다.
